# respire-client2 新用户初始化 Wizard 方案

## 目标与边界

在首次启动时，用一个可恢复的分步向导完成云端同步选择、注册/登录、Super Password 保存确认，以及本机嵌入模型、计算设备、权重下载和推理启用。复用现有 Runtime/CLI 接口与桌面视觉，不新增前端框架、云账户体系或第二套模型管理器。

本方案只覆盖 onboarding 编排及必要的偏好字段、共享组件和测试；不实现账户或模型业务，不自动改云端同步，不提交或发布。

## 已核实现状

- Wails v3 + Go，无前端构建链。首启语言层位于 `internal/desktop/frontend/client.js` 与 `workspace.html`。
- 注册/登录已有 `auth_register` / `auth_login`，凭据经 CLI host RPC stdin，不进入 argv；兼容要求见 `docs/cli-host-input.md`。
- 注册回执已能提取并显示 Super Password，见 `frontend/pages/authentication.js`；离线 `keygen` 也会返回恢复材料。
- 模型目录提供 BGE-M3、BGE-base-zh-v1.5、BGE-M3-Distill-8L；下载、SHA-256 校验、暂停/继续和模型切换均已实现。
- 现有 ONNX 限制：GPU 在 Linux 不提供，NPU 只在 Windows 提供。CLI 的 MLX 后端虽在开发中，但客户端当前固定 `backend: "onnx"`，本版不把 NPU/MLX 宣传为可用能力。
- 现有模型页 `models.js` 的 `variantStatus` 有重复定义，后者覆盖了下载进度展示；向导复用下载流程前先消除该重复，避免两套进度行为。

## 交互流程

采用居中卡片与左侧/顶部步骤条，延续现有纸张色、描边和 rem 尺寸。每步只提出一个问题；上一步保留下一步之前的输入，但认证密码不保存到磁盘。

1. **语言**
   - 合并现有 `first-language` 层为 Wizard 第 1 步，避免两个首启弹层竞争。
   - 选完即保存语言，Wizard 和背景界面同时更新；后续可中英文切换。

2. **是否云端同步**
   - 标题：“要在其他设备上使用你的记忆吗？”
   - 推荐项“启用云端同步”：说明多设备访问、加密同步及需要账户；不宣称零知识，除非服务端契约另有实证。
   - 备选项“仅在此设备使用”：说明不同步、仍可本机记忆和语义检索，稍后可在“账户与空间”启用。
   - 选择云端后进入注册/登录；选择离线则跳过账户步骤。

3. **注册或登录**
   - 同页切换“创建账户 / 已有账户”，保留服务器地址，默认 `https://api.rsrs.rs`。
   - 注册：账户、至少 8 位密码、重复密码；提交前校验，失败留在本页，不回显密码。
   - 登录：账户、密码、按需 Super Password、按需 TOTP；不新造 OAuth 流程。
   - 成功后验证 `session.has_token` 和本机密钥状态；询问是否自动同步，默认开启，通过 `autosync_set` 保存。只有认证与同步设置成功才标记此步完成。
   - Runtime/CLI 未连接或不支持 host RPC 时，给出去“更新”处理的入口及“稍后配置，先离线使用”；后者必须再次确认，不能把失败静默记为已配置云端。

4. **保存 Super Password**
   - 注册、离线 keygen 或登录实际返回新恢复材料时显示；普通登录未生成新材料则不伪造此步骤。
   - 独立只读区域展示 CLI 原始恢复材料，不拆造密钥；提供“复制恢复材料”。解释登录密码不能替代 Super Password，丢失后服务端无法帮助恢复本机密钥。
   - 勾选“我已将恢复材料保存到安全位置”后才允许继续；不能用 Escape/关闭按钮绕过。
   - 材料只留在当前页内存；关闭、前进、刷新后清空，不写 `localStorage`、preferences、日志或操作记录。

5. **选择模型**
   - 先说明收益：本地嵌入模型把记忆转为向量，用于语义召回、相似内容判断和整理；计算在本机完成，不需要把记忆正文发送给云端模型服务。下载需要网络并占用磁盘；跳过则只保留不依赖向量的功能，部分检索/整理操作可能不可用，之后可补装。
   - 默认 **BGE-M3**：多语、1024 维、质量和兼容性优先。
   - **BGE-base-zh-v1.5**：中文为主、较小下载和资源占用。
   - **BGE-M3-Distill-8L**：多语、较轻量，适合资源受限设备。
   - 卡片显示语言、维度、定位；具体下载大小随下一步权重动态计算，不写死过期数字。
   - 提供“暂不下载”，并明确其功能后果。

6. **选择计算设备**
   - **CPU（默认）**：兼容性最好、无需额外驱动，速度相对慢。
   - **GPU**：适合频繁/批量向量计算，速度和显存占用通常更高；Linux 本版禁用并说明。
   - **NPU**：面向支持的 Windows 硬件，强调能效；仅在 Windows 显示为可选。当前前端不能核实具体硬件/provider 是否就绪，因此选择页必须标注“需兼容硬件和引擎，启用时将做实际推理验证”，并提供安装引擎入口，不把 OS 判断当作硬件检测。
   - 权重跟随设备：CPU 默认 `quantized`；GPU/NPU 默认 `fp16`。切换设备时同步更新预计下载量。
   - 高级展开允许改选其他已支持权重，但首屏不要求用户理解量化格式。下载所需文件为分词器 + 所选权重；不重复下载校验通过的权重。

7. **确认并开始**
   - 汇总：云端选择/账户状态、模型、设备、权重、下载量、保存位置。
   - 主按钮“下载并启用”；次按钮“稍后下载”。用户确认前不触发下载或引擎变更。

8. **执行与完成**
   - 统一显示“下载 → SHA-256 校验 → 注册/加载模型 → 真实推理验证 → 索引安排”的阶段、字节进度和当前文件。
   - 复用现有暂停、继续、取消、失败重试。关闭 Wizard 不取消下载；重新打开后从任务状态恢复，不重复提交。
   - 成功后进入“Agent 工具配置”（第 9 步），并提供“直接开始”跳过；索引可继续后台构建，但要区分“模型已可用”和“全部索引完成”。
   - GPU/NPU 验证失败时沿用 Runtime 回退机制，清楚展示实际启用的 CPU/权重和原因，不显示为所选设备成功。
   - 失败可重试当前阶段或保存选择退出到模型页；只有全部必需步骤成功才写 `onboardingCompleted`。

9. **Agent 工具配置（可选）**
   - 读取 `inject-targets` 展示已安装的 Agent 工具；提供三种配置方式：**提示词 + 插件**（推荐，`inject-set` scope=all）、**仅提示词注入**（scope=prompt）、**仅安装插件**（scope=plugin）。
   - 方式决定可勾选范围：仅提示词不含插件型宿主（mode=plugin），仅插件只列带 `plugin` 的宿主；全部列出后按目标复选。
   - 「应用到所选」逐个调用 `inject-set {id, enable:true, scope}`，按目标回报成功/失败（复用注入页的回执文案）；失败不阻断其余目标，完成后重读目标状态。
   - 复用「配置Agent」页的接口与规则，不复制第二套注入逻辑；跳过或应用后均以「开始使用 Respire」完成向导，本步骤不阻塞 `onboardingCompleted`。

## 首启判定与可恢复状态

在 `host.Preferences` 增加版本化的非敏感向导状态，存于 `<root>/client2/preferences.json`：

```json
{
  "onboardingVersion": 1,
  "onboardingCompleted": false,
  "onboardingStep": "sync",
  "onboardingSyncChoice": "cloud"
}
```

- 旧版无字段用户默认 `onboardingCompleted=true`，避免升级后被迫重走；仅全新偏好文件进入 Wizard。
- 导入旧设置同样迁移为已完成；提供“设置 → 重新打开初始化向导”人工入口。
- 只持久化版本、步骤、云端意向；不保存密码、Super Password、TOTP、恢复材料。模型/设备/权重选择以 Runtime 当前状态为准，内存中的未提交选择丢失后可重选。
- 启动顺序：读取偏好 → 语言/向导路由 → 等 Runtime 可用 → 根据真实会话、任务和模型状态恢复。每个外部副作用以原请求回执/实际状态判完成，不能以前端步骤标记代替。
- Runtime 暂不可用时允许浏览和稍后设置，不允许提交认证、模型或完成标记。

## 实现拆分

### A. 偏好与桌面契约

- `internal/host/manager.go`：新增上述字段、默认值、旧配置迁移及步骤/枚举校验；继续原子写入。
- `internal/desktop/api.go`：偏好输入改为在现有完整偏好上做 patch，保留未由表单展示的字段；修正当前重建 struct 时可能漏掉 `runtimeAutoRestart` 的问题。
- `internal/desktop/business.go`：设置导出/导入保持兼容，导出绝不包含凭据或恢复材料。

### B. Wizard 与共享 UI

- 新增 `frontend/onboarding/wizard.js`：纯步骤状态机、Runtime 状态恢复、分支导航、提交防重入。
- 新增 `frontend/onboarding/onboarding.css`（或在 dashboard.css 末尾按 CRLF 维护）：步骤条、选择卡、恢复材料区、进度和响应式布局。
- `client.js` / `workspace.html`：用 Wizard 替换独立首启语言层；普通路由在 Wizard 未完成时不可绕过，后台轮询不得重建当前表单或清空密码。
- `ui/i18n.js`：补齐中英文静态文案；动态错误保留 Runtime 原文。

### C. 认证与恢复材料复用

- 从 `pages/authentication.js` 抽出 `runAuthentication(kind, values)` 和 `issuedRecoveryMaterial(envelope)`，供账户页和 Wizard 共用。
- 继续调用 `auth_register` / `auth_login` / `keygen` 的现有 request ID 与回执恢复逻辑；未知结果只查询原请求，不自动重放。
- 恢复材料确认组件同时用于 Wizard 与账户页，消除“一处要求保存确认、另一处绕过”的差异。
- 云端成功后复用 `autosync_set`，回读 session/config 验证；失败不提前推进。

### D. 模型下载与启用复用

- 从 `models.js` 抽出模型元数据、设备可用性、下载对话框/进度控制、应用引擎函数；模型页与 Wizard 共用，不复制业务规则。
- `model-download` 继续下载固定 revision 的文件并校验。所需权重存在时跳过下载，直接进入启用。
- `m3` 调 `model_engine_apply`，然后 `model_prepare` 安排基线/索引；其他模型依次 `model-configure`、`model-switch`，轮询 `model-profile-state` 直至 ready/failed。
- 下载任务与 Runtime 模型操作分别跟踪，二者不能混用“完成”状态。切模型前检查已有任务/切换冲突。
- `models.js` 先删除重复的 `variantStatus` 第一版，并合并保留下载中、切换中、已安装三种状态，保证 Wizard 与模型页行为一致。

## 验证方案

1. **Go 单元测试**：新偏好默认/迁移/校验、旧导入不重跑、步骤枚举拒绝、完整偏好 patch 不丢字段；不写入真实 `~/.rsrs`。
2. **前端状态机测试**：cloud/offline 分支、返回、刷新恢复、未确认恢复材料不能前进、跳过模型的后果提示、认证/下载/启用失败不标完成、重复点击不重复提交。
3. **mock UI 验证**：扩展 `.verification/ui-mock/server.mjs`，覆盖注册、登录、TOTP、Super Password、三模型、三设备及失败回执；截图核对中英文、亮暗色、紧凑窗口、键盘焦点和进度。
4. **隔离 Runtime 验证**：使用专用 `RSRS_DATA_DIR` 和 `RSRS_RPC_PORT`。测试全新安装、旧配置升级、离线路径、注册/登录路径、断网/旧 CLI、刷新恢复；实际注册使用专用测试账户，不使用真实用户凭据。
5. **模型真实验证**：至少跑 CPU 默认完整下载和推理；分别验证文件已存在不重复下载、暂停/继续、取消、校验失败、GPU/NPU 不可用和验证失败回退。GPU/NPU 实机不可用则明确标为未实测，不能仅凭 mock 宣称通过。
6. **回归与安全**：`go test ./...`、`go vet ./...`、全部 JS `node --check`、现有模型页/账户页流程；检查进程 argv、preferences、日志、操作记录及导出文件不含密码、TOTP 或恢复材料。

## 主要风险与处理

- **旧用户被误判为新用户**：以偏好文件是否已存在为迁移依据，测试覆盖。
- **恢复材料外泄**：只在内存展示；不复用会持久化参数的通用表单状态，验收检查所有落盘面。
- **下载完成但启用失败**：完成标记必须等待真实推理结果；保留重试和离线退出。
- **设备能力被夸大**：当前只按 OS 提供入口，NPU/硬件 provider 不做虚假“已检测”标签，以真实 probe 为最终判据。
- **后台刷新破坏输入**：Wizard 独立局部更新；只有任务阶段和进度允许轮询更新。
- **模型页与 Wizard 行为漂移**：共享认证、下载、启用与恢复材料组件，禁止复制两套实现。
